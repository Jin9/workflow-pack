## workflows-ui (HELL FACTORY browser sim)

A top-down, Pokémon-8-bit **"agentic office" simulation that runs in the browser** — a grid of department rooms connected by a red-carpet corridor; ten named agents BFS-path between rooms, claim seats, and sit at desks while a player avatar (`YOU`) roams. **Vite + React 18, plain JS, no TypeScript, no test runner.** It doubles as **the pipeline console** via the `src/console/` layer (below); with no engine at `/api` it degrades to the fully autonomous sim. The visual design was prototyped in Claude Design and ported here intended pixel-identical. Verification is **visual only** via a headless Brave screenshot (`npm run dev` → `http://localhost:5173`; macOS has no `timeout`, so poll the port with a bash loop). Build: `npm run build` → `dist/`.

The app renders into a **fixed 1800×1013 `#stage`** (in `index.html`) that an inline script scales to fit the viewport (letterboxed); React mounts into `#root`; pixel fonts are **vendored** via `@fontsource` imports in `main.jsx` (offline — no Google-Fonts links). `src/` modules form a **strict dependency chain — do not reorder**:

```
map.jsx → furniture.jsx → sim.jsx → avatars.jsx → App.jsx → main.jsx
```

- **`map.jsx`** — the world: a `COLS=50 × ROWS=36` tile grid at `TILE=28`px. Tile codes `W/F/C/D/E`; `ROOMS[]` is the source-of-truth room table; exposes walkability helpers, the mutable `OBSTACLE` layer + `setObstacle`, and the memoized `MapLayer` renderer.
- **`furniture.jsx`** — tile-aligned 8-bit sprites with real collision. ⚠️ **Import-time side effects:** building its `FURN`/`SEATS` layout calls `setObstacle(...)` and computes the corridor-reachable `SEATS` pool, so it **MUST execute before the world is initialized** — `sim.jsx` importing `SEATS` from here guarantees that order.
- **`sim.jsx`** — pure sim logic (no JSX): `initWorld()` builds the 10 agents (8 squad roles + Tia + Mia, productivity 88), `tickWorld()` advances one step, `bfsPath()` routes through doorways, agents `assignSeat`/sit, `pushFeed` emits log lines.
- **`avatars.jsx`** — top-down person sprites (facing-aware, walk animation) + per-room `Rugs`/`Signs`. **`tweaks.jsx`** — reusable floating "Tweaks" panel (local state → `localStorage`, opened via launcher or **`T`**).
- **`App.jsx`** — composition + interaction: the sim loop (`setTimeout`, `320/speed` ms), keyboard (WASD/arrows w/ wall+furniture collision, `Space` pause, `Tab` select, `1–4` state, `M` mode, `N` add, `Q`/walk-out → quit overlay), and renders `Floor` + `CommandBar` + `ConsoleOverlay`. **`styles.css`** — all `.ao-*` styling (verbatim from the prototype) + the `.hfc-*` console styles; holds `#stage` dimensions + `image-rendering: pixelated`; imported once from `main.jsx`.
- **`console/`** — the pipeline-console layer ABOVE the chain (imports only downward into `sim`/`map`): `engine-client.js` (fetch wrapper, engine down ⇒ `null`, sim never throws) → `adapter.js` (anti-corruption `normalizePack`; 2s ETag poll; `staticPack()` keeps the serverless replay path) → `director.js` (pack delta → agents walk to stage rooms, gate approver parks in `CONF`, timeline → feed; directed agents carry `directorPost` and get herded back if the autonomous sim wanders them) → `overlay.jsx` (run picker, ONLINE/OFFLINE badge, request form, gate inbox with named-approver input + per-gate verdict vocabulary, worst-of RAG chip, feed; hotkey **`C`**). Vite dev proxies `/api` → `:8000`; prod = FastAPI serves `dist/`.

Conventions: **state lives in a mutable `world` ref** (the sim mutates in place; a `useReducer` bump via `force()` re-renders — never store `world` in React state). **Coordinates are tile-space** `{col, row}` × `TILE` (28) at render time only; new furniture/rooms must stay on-grid and leave door-entry tiles walkable, or agents can't reach seats. `Sidebar`/`Metrics`/`Roster`/`Feed` in `App.jsx` are **intentionally unmounted** (kept with CSS; mount `<Sidebar>` to restore). Edit `ROOMS` in `map.jsx` and the matching `furniture.jsx` blocks **together** — they share tile coordinates. Operational boundaries (approval gates, git workflow) live in the root `AGENTS.md`.

## Skills are the core unit — and `skillify` builds them

Almost everything here is a skill: a folder with `SKILL.md` (YAML frontmatter + body) and optional `schemas/`, `references/`, `templates/`, `scripts/`. Skills are authored/maintained via the **external `skillify` meta-skill** at `~/.claude/skills/skillify/`, and every skill must pass its two deterministic gates before it is done:

```bash
python3 ~/.claude/skills/skillify/scripts/quick_validate.py <skill-dir>   # frontmatter + structure
python3 ~/.claude/skills/skillify/scripts/check_links.py   <skill-dir>   # local reference links
```

House-style frontmatter (banking-grade skills under `workflows/skills/`): `name`, `version`, `description` (must contain literal *"Use when …"* trigger phrases **and** *"Do NOT use …"* negative triggers, **no `<`/`>` angle brackets**), `stage_type`, `input_schema`, `output_schema`, a `banking_grade {idempotent, reversible, audit_level, pii_handling, tier_default, tier_adaptable}` block, `expected_duration_p95_seconds`, `max_retries_recommended`, `fallback`, `compatibility`. Keep frontmatter **flat** (skillify rejects nested `metadata:`). Body shape: Purpose → When to use (with explicit "not this skill" scoping) → Input → Procedure → Output (carries an `audit_id`) → Failure modes → Constraints → References → human approval gate/verdict. Keep `SKILL.md` ≤500 lines; push depth into `references/`. Cross-skill references use **bare skill names** (so they survive folder moves); output schemas thread an `audit_id` for the audit trail.

## The runtime engine (`engine/`)

The recorded departure from the old static-only posture (ADR `.claude/history/2026-07-04-live-engine-adr.md`): a minimal local Python runtime that actually executes the 28-stage YAML. **Replay mode is the token-free default** (byte-verbatim ShopPilot corpus, byte-deterministic); **live mode is opt-in per stage** via `engine/config/runtime-binding.yaml` — live today: S0 haiku + S1a/S1b + the design leg (tl-design · plan-review · contract-design) + both code reviews on headless opus; **T1/T3 run the REAL test suites** via the script executor (`gate-runners.yaml`: `go test -race -json` over the 4 corpus services + `vitest run` — no LLM in machine-threshold gates); S4a/S4b's claude-agent-sdk binding is proven-live but commented out for cost; ux-intake stays replay (needs a real UX drop) and qa-validate stays replay (GAP-05 execution node — never fabricate evidence).

- **Fail-closed:** loader (exact pins == folder versions; refs resolve; `from_stage` ⊆ ancestors) · DUAL-schema validation per artifact (skill `schemas/output.json` + boundary + `required_fields`, mirroring `_sim/validate.py`; INDEX/run-plan boundary-only) · unknown verdict vocab → human. The headless/SDK prompt carries BOTH schemas + the input inside a data fence (data, not instructions). **Ref-chain hydration** (mapping.py): ba-research's `epics[]`/`story_files[]` refs are dereferenced into inline Epic/Story objects for the inline-era consumer contracts, and the workflow's one `idempotency_key` rides in every payload.
- **Gates:** `engine/config/gates.yaml` (all 28 stages, schema-validated, mirrors the s1-discovery `human_review` block). Blocking gates park the run until a verdict with a **named approver** — no code path can auto-approve a sync-named gate (test-proven). **`required_roles` makes a gate a QUORUM**: the S1b three-amigos gate releases only after a distinct named human has signed for each of ba-lead / dev-lead / qa-lead, and a non-`agreed` verdict loops the breakdown back with the reviewers' own findings rather than failing the run. Typed HITL records + hash-chained `runs/<id>/events.jsonl` (digests only — never raw_request/PII).
- **Run dirs** mirror the ShopPilot layout, so `validate-run` and `rendering-delivery-review-console` consume live runs unchanged.
- **A fully-autonomous green run through the design leg is impossible BY DESIGN for regulatory-scoped requests** (proven live, run-77777777): the BA brief correctly carries P1 governance gaps (e.g. Legal-absent on PDPA scope) and the live red team correctly BLOCKs a governance-blocked plan; auto-resolving P1 blockers is on the never-do list. Do **not** "fix" this by relaxing the gate, widening the verdict routes, or bumping `max_loops` — a named human clears the governance gap, then the run proceeds.
- Commands: `engine/.venv/bin/python -m engine {replay|serve|validate-run|verify-audit}`; tests: `engine/.venv/bin/python -m pytest engine/tests -q` (token-free). API + details: `engine/README.md`. Human-queued failures resume via a typed HITL action: `POST /api/runs/{id}/stages/{stage}/resolve {action: retry|abort, resolver}` (named resolver required). SAGA: the compensating skill executes against `compensating_action.schema_ref` (`revoke-receipt.json`, live-proven); loop_backs thread the reviewer's findings into the re-run.

The static validation stack (YAML + `jsonschema`/`ajv` draft-07 + `depends_on` graph + optional `spec-review/` gate) still applies before any run.
- **Live pipeline skill versions are exact-pinned** — `skill_version: "2.0.0"`, never `"^2.0.0"`, in `workflows/delivery-pipeline.yaml` (supply-chain reproducibility). Bumping a skill means updating **both** its folder `version` **and** the YAML pin (single source of truth).
- **Never rewrite recorded provenance.** Reference-corpus `audit_id`s and `processing_metadata.skill_version` are grandfathered history — the house `audit_id` formula applies to LIVE derivations only. Adding a *missing* field through the generator is fine; changing a recorded value is falsification.
- **Never fabricate corpus data.** A corpus value must be honestly derivable from the run's own bytes (real file counts/hashes, the run's own receipt id, real `STORY-*` ids) or it does not go in. Synthetic latencies, invented statistics, and retroactive rubric traces are out — an unmeasurable row is `insufficient_data` with a reason, never a guessed number.
- **Design artifacts recommend/record; they never operate the pipeline.** The `agentic-workflow-design` skill and the delivery-pipeline design docs draft supervision; they do not run, deploy, or relax a gate. Deploy-class actions require a sync named-human approval.
- `research-vault-librarian` (external, targets an Obsidian vault) is **read-only** — it proposes patches, never writes the vault.
- **Generator scripts are deterministic by contract** (the `reference/repo-generator/` stamper; the dashboard `build.py`) — no `now()`/randomness; same input → byte-identical output.
- **Offline HTML viewers** embed their data as a JS `const PACK` (placeholder values contain `<…>`, so they need an `esc()` HTML-escaper). The S1 viewer's `/* INJECT */` block comment must **not contain `*/`** (write `EPIC-(DOMAIN)`, not `EPIC-*/…`) — a stray `*/` closes the comment early and breaks the viewer.
