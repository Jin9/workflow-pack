# 2026-07-28 — BA leg v2: breakdown + three-amigos gate + elaboration (27 → 28 stages)

Feedback on the BA steps asked for four things at once: keep the analysis deep, make
the reports simpler, cut what is not needed, and — structurally — break epics and
stories down and **review them with a developer and a tester before writing detail**,
group epics by **business dependency**, and split the skills that do too much.

Design spec: `docs/superpowers/specs/2026-07-28-ba-leg-v2-design.md`.
Staging (kept for the regenerator + its validator): `tmp/runs/ba-leg-v2/`.

## What changed

`eliciting-banking-brief` (16,902 lines, 13 procedure steps, 16 references, two
renderers) is retired and replaced by two focused skills with a human gate between:

```
S0 intake → S1a s1-discovery →[BA lead]→ S1b ba-breakdown →[THREE-AMIGOS]→ S1c ba-research → S1.5 …
```

The elaboration node **keeps the stage id `ba-research`**, so the boundary contract
and all five downstream consumers are untouched.

## Decisions recorded

**D1 — how `agreed` releases.** `gates.yaml` carries `on_field: state` +
`proceed_when: agreed` rather than adding `agreed` to the fleet-wide
`RELEASE_VERDICTS` constant. The gates.yaml → workflow mirror check only fires for
stages that carry a `human_review` block in the pipeline YAML, so gates.yaml may set
these unilaterally; deliberately NO `human_review` block was added to the
ba-breakdown stage, to avoid a second source of truth.

**D2 — corpus directory names.** Promoted verbatim: `S1b-breakdown/` and
`S1c-brief/`. The only hard constraint was the four `../S1b-breakdown/...` literals
inside the S1c manifest. `S1b-ba-brief/` is deleted, not kept — its producer, shape
and epic/story ids all changed.

**D3 — the S1a provenance fork (human decision).** The corpus S1a discovery carried
a recorded `audit_id` (`9d4e1f8a-…`) while the regenerated breakdown declared
`upstream_refs.discovery_audit_id` = the house-derived `9ddddd53-…`. Promoting only
S1b/S1c would have left the breakdown pointing at a discovery that does not exist in
the corpus — fabricated linkage. **Chosen: replace S1a with the regenerated
artifact**, superseding the old id. The corpus is an oracle, not an archive, and git
retains the superseded bytes. Recorded here because it is a deliberate departure from
"never rewrite recorded provenance" — the doctrine still holds for values *within* a
retained artifact.

**D4 — the `scope` pick is DEFERRED, not done.** S0 emits `scope_sheet: {envelope,
contract}`; the new skills declare a flat advisory `scope`; `researching-ba-problem-space`
declares neither. Any of the three obvious wirings fails a contract lint, and
resolving it means renaming across S0's output schema, `run-plan.json`, the YAML
`required_fields` and three consumer input schemas. That is its own change. **S0's
scope sheet is therefore still thrown away at runtime** — the pipeline passes only
`normalized_request`. Both new skills already accept `scope`, so the wiring is a
follow-up, not a rebuild.

**Loop-back scope (human decision).** Built, not deferred. Without it a
`split-stories` verdict — an ordinary review outcome — would have terminated the run,
making the gate's verdict vocabulary a lie.

## New engine capability

- **Quorum gates.** `gates.yaml` `required_roles` + `GateSpec.required_roles`. A gate
  releases only after a **distinct named human** signs for each role. A role may not
  sign twice; one human may not cover two roles; a dissenting signature resolves the
  gate immediately. `GateInstance` accumulates `approvals[]` while the single-approver
  fields keep carrying the decisive signature, so `as_record()` stays compatible.
- **Gate loop-back.** `post_verdict` on a non-releasing verdict now threads the
  reviewers' own findings into `loop_feedback` and resets the downstream cone.
  `_apply_failure` no longer overwrites gate-sourced feedback — that would have
  re-derived guidance from the artifact and sent a blind re-run.
- **Nest + hydrate together.** They were mutually exclusive (`nest_key is None`).
  The breakdown pack needs both, including two bare path-string refs
  (`rules_file` / `domain_file`). Refs now also refuse to escape the run directory.

## Defects found and fixed en route

### Pre-existing (surfaced by this change)

| Defect | Consequence |
|---|---|
| Replay's sidecar copy used a non-recursive `glob("*.json")` | Per-epic subdirectories never reached the run dir, so every hydration ref dangled |
| `SKILL_SCHEMA_EXEMPT = {"ba-research"}` | The old skill's output schema could not describe its own manifest; the exemption is gone and the set is now empty |
| `test_input_validation`'s breach assertion guarded on an attribute `AuditLog` does not expose | The assertion was vacuous — always `[]` |
| `smoke_subset.test_case_ids` compared epic-shaped ids against story ids | The smoke subset was **always empty** |
| `_sim/simulate.py` hardcoded epic ids in 4 places | A BA regroup would leave the qa-plan internally dangling, which no validator checks |
| `e31` in the drawio pointed plan-review's loop-back at the BA brief | The YAML loops it to `tl-design` |
| dashboard-data.json skill pins | 20 stages drifted from the YAML pins |
| Shared test helpers imported from `conftest` | Created a second module object and made test order significant (intermittent hang) |

### Introduced by this change, found by an adversarial review pass and fixed

An independent skeptic pass was run against the finished work rather than trusting the
self-report. It found two P1 defects in the quorum gate as first written:

| Defect | Consequence | Fix |
|---|---|---|
| "Distinct named humans" compared approver names by exact string equality | ONE person released the three-amigos gate by signing `Khun Pim`, `khun pim` and `Khun  Pim` — the guarantee fell to a capitalisation | `_identity()` normalises case and whitespace before the distinctness check; parametrised regression test |
| The gate compared only the VERDICT to `proceed_when` | Three `agreed` verdicts released a breakdown whose own `state` was `blocked` with an unresolved P1 governance gap — the documented "no verdict clears a P1 gap" was a comment, not a control | New `release_requires_field_value` gate field: the gate can never release unless the artifact's `on_field` holds the required value, whatever the humans vote |

A third finding was a **fabrication**: the generated `S1c-brief/INDEX.json` named three
humans in `upstream_refs.amigos_approvers`, i.e. corpus data asserting a gate decision
no run had recorded. Removed — who signed is a HITL record in `events.jsonl`, written
by the run that actually collected the signatures.
