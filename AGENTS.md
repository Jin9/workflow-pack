# AGENTS.md

Workspace-level agent guide for **workflow-pack** — a research/experimentation
workspace for **agentic SDLC workflows and Claude Code skills** (not a single
buildable app). It holds a few largely independent subprojects plus top-level
design artifacts about one flagship agentic delivery pipeline.

> **`CLAUDE.md` is the authoritative, fuller guide** (current state, conventions,
> validation, dashboard internals). This file is the short operational boundary
> sheet; where the two overlap, `CLAUDE.md` wins.

## Boundaries

### Always allowed (no approval)

- Read tracked files; run the skill validators and the static pipeline validation;
  run the dashboard round-trip (`extract.py` / `build.py`); take offline screenshots.
- Run the engine's **token-free** paths: `python3 -m engine replay`, `validate-run`,
  `verify-audit`, and the pytest suite (`engine/tests`). Replay proves scheduler,
  gate, audit, and emitted-output-contract behaviour; it does **not** prove live
  stage-to-stage input compatibility.
- Run the scripted T-gate suites (`gate-runners.yaml`: `go test -race` over the corpus
  services, `vitest run`) — local test execution, no LLM, no tokens. These suites
  target the checked-in ShopPilot reference corpus, not freshly generated run output.

### Requires human approval first

- **Deploy-class actions** — these require a synchronous, named-human approval gate
  (design artifacts only recommend/record; they never operate the pipeline).
- **Promoting a staged skill** from `tmp/runs/<name>/` into `skills/` — staging is
  agent work; promotion is a separate human-driven step.
- **Adding or upgrading dependencies** in any subproject — propose first; do not
  install unilaterally.
- **Live engine runs** (`mode: live` in a run request) — they spawn real agent
  subprocesses and spend tokens; confirm scope + cost first. Gate verdicts AND
  human-queue resolutions (`…/stages/{stage}/resolve`) always need a named human;
  that approval does not waive the structural S6/S7 hard stop below.

### Prohibited (with the allowed alternative)

- Do not read, search, glob, or otherwise access the sibling `../archive/`
  (`/Users/admin/Desktop/project/research/archive/`, no leading dot, **outside**
  this repo) without explicit per-request permission — scope every grep/glob and
  any dispatched Explore/general-purpose subagent to **exclude** it. If archived
  content seems necessary, **ask first**.
- Do not ship non-offline HTML — the dashboard, run consoles, and all viewers must
  stay offline: no `https`, `src=`, CDN, or `@import`; web citations are bare host
  text only.
- Do not echo real PII — redact (e.g. `PII:REDACTED:CLASS=NRIC`). Workspace-wide
  banking rule.
- Do not relax a pipeline quality gate to make a run pass — no softening
  `engine/config/gates.yaml`, no widening the engine's verdict routes, no bumping
  `max_loops`. A live red-team `BLOCK` or a P1 governance gap is a **named human's**
  decision; an autonomous green run through the design leg is impossible **by
  design** for regulatory-scoped requests (proven live — see `CLAUDE.md`, engine
  section).
- Do not caret-range live pipeline skill versions — exact-pin (`skill_version:
  "1.0.0"`), and bump both the skill folder `version` and the YAML pin together.
- Do not make generator output non-deterministic — the `reference/repo-generator/`
  stamper and the dashboard `build.py` are deterministic by contract (no `now()` /
  randomness; same input gives byte-identical output).
- Do not claim production readiness from a green replay, `validate-run`, or the
  Quality-Gate Board. Those prove the checked-in artifacts and engine mechanics,
  not live handoff compatibility or a deploy-blocking quality barrier.
- Do not describe scripted T1/T3 as testing code generated by the current run —
  `engine/config/gate-runners.yaml` targets `tmp/runs/shoppilot/`.
- Do not bind a real control-plane executor to `release-handoff` / `prod-validate`,
  or perform a deploy-class action through this engine, until **all** of these are
  structurally enforced and test-proven:
  - every assembled stage payload validates against the consuming skill's
    `schemas/input.json`;
  - T1–T10 form a blocking pre-release barrier, and T11/T12 plus production SLO
    evidence form the final promotion barrier;
  - the synchronous named-human release approval happens **before** the
    irreversible action;
  - compensation covers release rejection, abort, timeout, smoke/canary failure,
    and an explicit rollback verdict; and
  - scripted gates target the current run's isolated generated worktree.
- For bulk wipes/resets, do not `rm -rf` — default to a timestamped move into
  `~/.Trash/<name>-reset-YYYYMMDD-HHMMSS/`, and also snapshot tracked-but-untracked
  state to a readable `tmp/.backups/<ts>/` (macOS TCC blocks reading back `~/.Trash`).

### Current pipeline limits

- `validate-run` validates emitted stage artifacts (skill output schema + workflow
  boundary schema + `required_fields`). The engine does not currently validate an
  assembled stage payload against the consuming skill's input schema; several YAML
  mappings therefore remain adapter work, not a proven typed handoff.
- Replay copies byte-verbatim artifacts from `tmp/runs/shoppilot/`; a successful
  28-stage replay validates orchestration and output compatibility, not whether a
  live stage can consume its upstream payload.
- `contract-design`, `backend-implement`, and `frontend-implement` are parallel DAG
  siblings. S3 does not currently feed either implementation stage, so do not call
  the running workflow contract-first.
- T1–T12 are leaf stages. They participate in the terminal run state, but T1–T10
  do not block `release-handoff`, and T11/T12 do not block `prod-validate`.
- In live mode, unbound stages still replay. Only T1/T3 are script-bound today, and
  both run against the reference corpus; `qa-validate`, S6, and S7 are not live
  evidence/deploy paths.
- Blocking gates open after their stage executor emits an artifact. That is valid
  for artifact review, but unsafe for an irreversible release action. Compensation
  currently runs only when an artifact routes to `rollback`, not for every
  post-release failure path.

## Commands

```bash
# Skill gates (both must exit 0 before a skill is "done")
python3 ~/.claude/skills/skillify/scripts/quick_validate.py <skill-dir>
python3 ~/.claude/skills/skillify/scripts/check_links.py   <skill-dir>

# Engine, token-free (full replay + dual-schema oracle + audit chain + tests)
engine/.venv/bin/python -m engine replay --run-id r1 --approve-as "Your Name"
engine/.venv/bin/python -m engine validate-run runs/r1 --strict
engine/.venv/bin/python -m engine verify-audit runs/r1
engine/.venv/bin/python -m pytest engine/tests -q

# The console backend (serves workflows-ui/dist at / when built)
engine/.venv/bin/python -m engine serve --port 8000
```

- **Pipeline execution goes through `engine/`** (ADR 2026-07-04; the Rust
  `squad-engine` stays archived): `engine/.venv/bin/python -m engine
  {replay|serve|validate-run|verify-audit}` — replay is token-free and default;
  live mode is per-stage opt-in via `engine/config/runtime-binding.yaml`. The
  static validation stack (YAML + `jsonschema`/`ajv` draft-07 + `depends_on`
  graph + optional `spec-review/` gate) still applies before any run.
- **Dashboard:** edit `dashboard-data.json`, then regenerate the bundle with the
  `roundtripping-dashboard-data-contract` skill (`extract.py` / `build.py`).
- macOS has **no `timeout`** — use a bash watchdog when bounding a command.

### workflows-ui

Top-down Pokémon-8-bit "agentic office" browser sim. **Vite 5 + React 18, plain JS,
no TypeScript, no test runner.** Doubles as the **pipeline console** via `src/console/`
(2s poll of the engine's `/api`; engine offline ⇒ fully autonomous sim). Verification
is **visual** via a headless Brave screenshot (no test suite). Pixel fonts are vendored
(@fontsource) — do not reintroduce CDN links.

```bash
npm run dev      # Vite dev server → http://localhost:5173
npm run build    # production build → dist/
# Headless verify (poll the port first; macOS has no timeout —
#   until curl -s http://localhost:5173 > /dev/null; do sleep 0.5; done):
"/Applications/Brave Browser.app/Contents/MacOS/Brave Browser" --headless=new \
  --screenshot=out.png --window-size=1800,1013 --virtual-time-budget=4000 \
  http://localhost:5173
```

**Passing** = the app renders without JS console errors **and** the floor layout matches
the prior visual baseline. **Code style:** no lint/format config — match the existing
tight inline style (e.g. `p.col = nc; p.row = nr; p.lastMove = now;`). **Git workflow:**
branch `feat/<slug>` or `fix/<slug>`; imperative commit subjects; PR body = what changed +
how verified (describe or attach the `out.png` screenshot diff); **do not self-merge** —
request human review.

The `src/` modules form a strict dependency chain (`map.jsx → furniture.jsx → sim.jsx →
avatars.jsx → App.jsx → main.jsx`); `furniture.jsx` has **import-time side effects**
(`setObstacle`) so it must load before `sim.jsx`. The console layer (`src/console/`:
engine-client → adapter → director → overlay) sits ABOVE that chain and imports only
downward into `sim`/`map`. Full architecture + conventions → root `CLAUDE.md`, section
**`workflows-ui (HELL FACTORY browser sim)`**.

Hard rules:

- Do not reorder `main.jsx` imports — `map → furniture → sim → avatars → App → main`
  enforces side-effect load order (`furniture.jsx` calls `setObstacle` at import time).
- Do not store `world` in React state — mutate `world.current` in place and call
  `force()` to re-render.
- Do not use raw pixel values — use tile-space `{col, row}` and multiply by `TILE`
  (28) at render time only.
- Editing `ROOMS` in `map.jsx` needs a matching `furniture.jsx` change → **approval**.
- Changing `#stage` dimensions (1800 × 1013) → **approval** (affects whole layout).
- Adding/upgrading npm deps → **approval**.
- Sim modules must never import from `src/console/` — the console imports downward
  only, so the sim keeps working with the console layer deleted.

Full detail → root `CLAUDE.md`, section `workflows-ui (HELL FACTORY browser sim)`.
